## What was implemented

1. **Reference vertical slice** (non-financial, non-stock, non-payroll)
   The following flow is exercised end-to-end across the Phase 01 tests:

   ```
   module manifest (platform_kernel)
   -> migration (001-005)
   -> entity registration (product_category, crm_lead)
   -> repository (generic CRUD for product_category; protected for crm_lead)
   -> action/lifecycle (crm_lead:create → submit → approve → cancel)
   -> sequence (product_category / invoice-style numbering in sequence tests)
   -> audit/outbox (every action writes audit + outbox)
   -> API route (/api/v1/x/product_category and /api/v1/action/crm_lead:create)
   -> view registration (kernel_reference_page bound to product_category)
   -> permission hook (product_category:create granted/denied)
   -> existing Octagon shell (no replacement; shell remains active)
   ```

   - `product_category` is the safe master/reference entity for generic CRUD, repository, view, and permission tests.
   - `crm_lead` is the workflow/state_machine reference entity for action/lifecycle and API tests.
   - The slice proves Arabic-localized view metadata and server-derived context without rewriting business modules.

2. **Legacy JSON adapter** (`platform/data/repositories/legacy-adapter.mjs`)
   - Read-only bridge from legacy `database.json` style collections to the new repository shape.
   - Reads nested collection paths (e.g., `collections.products`).
   - Presents legacy records with `company_id`, `created_at`, `updated_at`, `created_by`, `removed`, `version`, and `_legacy` markers.
   - Explicitly denies `create`/`update`/`delete`.
   - Allows migration scripts to compare legacy data before canonical migration.

3. **Authority registry (in evidence)**
   - The VNext salvage ledger (`docs/evidence/phase-01/source-manifest.json`) records source-to-target mapping and disposition.
   - The source lock (`docs/evidence/phase-01/source-lock.md`) records current and target authority for every inspected path.
   - No uncontrolled dual-write: legacy routes and current operational pages remain on their existing authority until their owning phase.

## Risks and decisions

1. **One writer**: The new repository is the writer for `product_category` and `crm_lead` in the reference slice only. All other legacy collections remain on their existing authority.
2. **No dual-write**: The legacy adapter is read-only. There is no shadow write path that could diverge.
3. **Reference slice only**: The slice proves the platform contracts; it does not migrate all legacy data or replace all legacy routes.
4. **Frozen zones respected**: Payroll, attendance, and employee records required by payroll are untouched.
5. **VNext remains source**: No VNext deployment is retained as a target product; code is merged into Octagon or documented as evidence.
