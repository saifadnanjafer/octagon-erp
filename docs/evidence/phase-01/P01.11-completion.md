## What was implemented

1. **Job registry** (`platform/kernel/jobs/index.mjs`)
   - Job descriptor and handler registration contract.
   - Persists jobs in `platform_jobs` with module ownership, schedule, handler, and enabled state.
   - Upsert semantics with `updated_at` tracking.
   - `list`, `listEnabled`, and `disable` operations.
   - Disabled-module jobs are removed from `listEnabled` via the enabled flag.
   - Lease/idempotency/retry/dead-letter interfaces are declared but not fully implemented; they are consumed by the outbox dispatcher for event delivery.

2. **Health registry** (`platform/kernel/health/index.mjs`)
   - Health contributor registration with id, name, check type, and check function.
   - Persists contributors in `platform_health_contributors`.
   - `check` and `checkAll` operations.
   - Checks are disabled when `enabled = 0` or when the check function throws.
   - No secret leakage: health checks return structured detail, not credentials or internal paths.
   - `status()` alias for `checkAll()`.

3. **Standard error classes**
   - `JobRegistryError` and `HealthRegistryError` with error codes.
   - `PermissionDeniedError` (P01.10) and `ApiError` (P01.8) provide consistent HTTP mapping.
   - Correlation IDs are propagated from execution context into error responses and audit logs.

4. **Tables** (Migration 005)
   - `platform_jobs` with module_id, name, schedule, handler, enabled, lease_id, leased_until.
   - `platform_health_contributors` with id, name, check_type, enabled.

## Risks and decisions

1. **Deferred full scheduler**: Actual cron scheduling, worker topology, provider integrations, external webhooks, credential vault, and support bundle export are deferred.
2. **In-process handlers**: Job handlers are registered as strings in Phase 01; the execution harness is a contract for Phase 08.
3. **No external side effects before commit**: The outbox dispatcher already satisfies the "no external side effect before transaction commit" invariant; job execution will inherit the same pattern.
4. **Health check safety**: Check functions are executed inside `try/catch` and only the error message is surfaced; no stack traces or secrets are exposed.
5. **Arabic UX preserved**: No UI changes; operational pages remain stable.
