This file adds two things the functional ledger deliberately left out:
**why** a thin/broken/zero-record page looks that way (an A-I root-cause taxonomy),
and what to **do** about it. Every cause is labelled MEASURED (traced to a concrete
runtime signal — a denied state, a 4xx/5xx, a null canonical API) or INFERRED (a
heuristic guess for the cases where no runtime signal distinguishes "nobody seeded
this resource" from "zero is correct" — those need one owner judgment call, not
another automated pass).

**Action-persistence gap, stated plainly**: nothing in this ledger proves a button
actually writes data. `inspect-pages.mjs` never clicks a page's own action buttons
by design (it must stay read-only). Every row says so explicitly rather than implying
proof that was never gathered — see `actionPersistenceEvidence`. Closing that gap for
P0/P1 pages is the job of the not-yet-written `test:functional-pages` suite.
