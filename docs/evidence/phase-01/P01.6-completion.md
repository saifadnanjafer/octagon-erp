## What was implemented

1. **Sequence Authority** (`platform/records/sequences/index.mjs`)
   - One canonical service for formatted number allocation.
   - Template placeholders: `{YYYY}`, `{MM}`, `{DD}`, `{PERIOD}`, `{#…}` (variable digit count).
   - Counter storage in `platform_sequences` keyed by `scopeKey:companyId:period`.
   - Reset policies: `none`, `fiscal_year`, `calendar_year`, `calendar_month`.
   - Gap policy vocabulary (`allowed`/`disallowed`) with explicit `allowed` default in Phase 01.
   - Transaction-neutral: `nextSeq` runs inside the caller's transaction boundary so it can be composed atomically with repository writes.
   - `peekSeq` for preview without allocation.
   - `resetSeq` for testing/period rollover.
   - Company and period isolation built into the key.

2. **Table ownership**
   - Counters live in `platform_sequences` (created by Migration 001).
   - `x_sequences` is also created by Migration 002 for future document-specific sequence records; the Phase 01 authority writes to `platform_sequences`.

## Risks and decisions

1. **Transaction neutrality**: `nextSeq` no longer opens its own transaction. The caller must wrap the business write and sequence allocation in one transaction. This is intentional to keep sequence allocation atomic with the authoritative record creation.
2. **Gap policy**: Only `allowed` is exercised in Phase 01. `disallowed` gap behavior requires stricter reservation/reconciliation and is deferred to later phases.
3. **Fiscal year**: Fiscal-year reset uses a configurable `fiscalStartMonth` and derives the year based on the current calendar month. Exact fiscal-period vocabulary will be hardened with finance in later phases.
4. **Legacy numbering**: Existing Octagon document generators remain untouched; they are not migrated to the canonical authority until their owning domain phase.
