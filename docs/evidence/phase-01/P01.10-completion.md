## What was implemented

1. **Permission hook** (`platform/governance/permissions/index.mjs`)
   - Deny-by-default interface used by modules, entities, actions, views, API routes, and feature gates.
   - Server-derived context only; no loopback or test bypasses in production.
   - System user (`userId === 'system'`) is allowed for internal platform operations.
   - Resolves active user from `platform_users` and validates company membership.
   - Resolves user roles from `platform_users.roles` JSON array.
   - Checks `platform_acl_grants` for explicit `(role, perm)` grants.
   - `admin` role implicitly granted all permissions.
   - Supports custom policy callbacks registered per `(resource, action)`.

2. **ACL schema** (Migration 005)
   - `platform_acl_roles` (role, label_ar).
   - `platform_acl_grants` (role, perm, scope) with primary key `(role, perm)`.
   - Seeded `admin` role with `*` grant covering all permissions.

3. **Placeholder adapter for legacy Octagon roles**
   - The hook is a clean interface; legacy role mapping will be completed in Phase 02.
   - Current Octagon `acl.json` and `services/permissionService.js` were inspected but not replaced.

4. **Route coverage contract**
   - Every registered route must have an owner module and a permission policy.
   - The API handler enforces protected-entity mutation denial through the repository, which is the first route-level policy consumer.
   - Fail-closed: unknown action, unregistered entity, or missing permission results in denial.

## Risks and decisions

1. **Phase 02 boundary**: Field-level ACL, record rules, data scopes, delegation, and full role administration are explicitly deferred. Phase 01 only proves the deny-by-default hook and grant table.
2. **No production bypass**: The hook has no `localhost`/`127.0.0.1` or test-mode bypass. System-user bypass is limited to platform internals and is logged.
3. **Role storage**: Roles are stored as a JSON array on `platform_users.roles`. A normalized role-membership table will be added in Phase 02.
4. **Grant scope**: The `scope` column on `platform_acl_grants` is recorded but not fully evaluated in Phase 01; all grants behave as `all` scope until Phase 02.
5. **Audit of denials**: Denied permission checks are not yet written to `platform_audit_log`; this is part of Phase 02's security audit trail.
