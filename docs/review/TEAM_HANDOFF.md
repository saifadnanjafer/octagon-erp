You've been asked to functionally and visually review a frozen snapshot of Octagon
ERP. This document is everything you need — you should not have to open the
repository's source code or understand how the app is built.

## Prerequisites

- Node.js (whatever version this repository already requires — if `npm run
  review:setup` complains about your Node version, that's the answer).
- A local checkout of this repository at the tag above.
- No database software to install — the review environment is self-contained
  SQLite, created fresh by the setup command below.

## Setup

From the repository root:

```bash
npm run review:setup
```

This creates a brand-new local database at `.review-data/octagon-review.db`
(never touches any real data), applies every accepted migration, and seeds 20
review sign-in identities plus fictional demo records across every reviewable
domain. It prints a summary when done. Your disposable sign-in password and
full login list are written to `.review-data/review-credentials.json` — that
file is local-only and git-ignored, never commit it.

## Start

```bash
npm run review:start
```

Starts the real Octagon application, pointed at the disposable database. It
prints the local URL (default `http://localhost:8080`) and the snapshot tag/SHA
it's running. Open that URL in your browser.

```bash
PORT=8090 npm run review:start   # use a different port if 8080 is busy
```

## Verify

```bash
npm run review:verify
```

Run this any time you're unsure the environment is healthy (database present,
fully migrated, identities and fixtures seeded correctly, no operational data
path active). It exits non-zero and prints exactly what's wrong if something's
off.

## Reset

```bash
npm run review:reset
```

Deletes the disposable database and regenerates it from scratch, deterministically.
Use this if you want a clean slate, or if you suspect your session's data got into
a confusing state. It never touches anything outside `.review-data/`.

## Switching language

Octagon defaults to Arabic (RTL). There is a language toggle button in the
application chrome (top of the page once signed in) that switches between
Arabic and English immediately, without needing to sign out. Review both
directions for any page you evaluate — see `VISUAL_REVIEW_ROUTES.md` for which
tours specifically call out Arabic vs. English passes.

## Switching role/identity

Sign out and sign back in with a different login from the table above. Each
login is a fully separate identity with its own permission grants — there is
no "impersonate" shortcut, which is deliberate: it's the only way to honestly
prove what a role can and cannot see.

## Recording findings

- Something is **broken**: use `BUG_REPORT_TEMPLATE.md` and add a row to
  `FUNCTIONAL_REVIEW_MATRIX.md` (or `UI_UX_AUDIT_MATRIX.md` for a visual issue).
- Something **works but should look/behave differently**: use
  `UI_CHANGE_REQUEST_TEMPLATE.md`.
- When your pass is done: fill in `REVIEW_SUMMARY_TEMPLATE.md`.

Always include the snapshot tag/SHA, your role login, language, and viewport in
every finding — see the templates for the full field list.

## Prohibited use of review data

- Never enter real customer, employee, financial, or payment information into
  this environment, for any reason — it is not needed and not sanitized for it.
- Never point this environment at a real payment provider, email/SMS gateway,
  or production system, even for a "quick test."
- If you ever see something in the review environment that looks like it could
  be real (not `[DEMO]`-labelled) data, stop and report it as a P0
  security-scope finding immediately — see `KNOWN_LIMITATIONS.md`.

## Known limitations

Read `KNOWN_LIMITATIONS.md` before you start — it lists what's intentionally
simulated (billing, marketing sends, event notifications), what's genuinely
deferred to BUILD-13+, and a couple of fixture-data approximations so you don't
mistake them for product bugs.

## Stopping local processes

`npm run review:start` runs in the foreground — press `Ctrl+C` in that terminal
to stop it. There is no background service to remember to kill. If you ever
need to confirm nothing is left running, check for a process listening on the
port you used (default 8080).
