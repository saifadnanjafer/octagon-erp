## What was implemented

1. **Versioned API router** (`platform/api/index.mjs`)
   - Mounts under `/api/v1`.
   - Separate namespaces:
     - `/api/v1/meta/entities` — query entity metadata.
     - `/api/v1/x/:entity` — query resources (list/read/summary) and generic CRUD for safe entities.
     - `/api/v1/action/:actionId` — command actions.
   - Stable envelope: `{ success, data, error, meta, correlationId }`.
   - Correlation ID propagation from header or query param, with fallback generation.
   - Bounded pagination/filtering via repository `list()`.
   - Request body size limit (1 MB default).

2. **Server-derived context**
   - Actor, company, branch, and idempotency key are derived from headers (`x-user`, `x-company`, `x-branch`, `x-idempotency-key`).
   - Request body cannot spoof actor/company/branch.

3. **Command action endpoint**
   - Accepts action IDs such as `crm_lead:create`.
   - Passes `idempotency_key` from header into the action body.
   - Returns action result with correlation ID.
   - Idempotent retry returns the same record for identical payload and key.

4. **Protected mutation denial**
   - Generic `POST /api/v1/x/crm_lead` returns `403` because `crm_lead` has a workflow/state_machine lifecycle policy.
   - Safe entities like `product_category` allow generic create/update/delete.

5. **Error handling**
   - `ApiError` with status code and error code.
   - Unknown routes return `404`.
   - Method mismatches return `405`.
   - Internal errors are redacted to a safe message in production mode.

## Risks and decisions

1. **Header-based context**: Phase 01 uses headers for user/company/branch because the full authentication/session layer is Phase 02. The API never trusts body-supplied scope.
2. **Idempotency**: The idempotency key is required for actions (`idempotency_policy: required`). Repeating the same key with the same payload replays the stored response; a different payload raises `IDEMPOTENCY_MISMATCH`.
3. **No legacy route replacement**: Existing Octagon routes remain active. The `/api/v1` namespace is additive and will absorb routes domain-by-domain in later phases.
4. **Error redaction**: Non-`ApiError` exceptions are returned as generic `internal error` with `500` status, preventing stack leakage.
5. **Payroll/Attendance**: No API routes added for payroll or attendance; they remain on their current authority.
